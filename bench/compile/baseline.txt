# SUB compile-time scaling (bench/compile/)
#
# Shapes: functions / variables / nested / chain / strings, sizes N = 250 500 1k 2k 4k.
# "subc" = native machine-code backend (`subc file -o o`, x86-64 Linux, gcc 14.2 -O2 build).
# "sub"  = `sub file c` (C backend; the tool chains it with the host compiler, so this
#          includes gcc -O2, not pure transpile). "subi" = interpreter startup
#          (lex + parse + analyze + run).
# Times are best of 3, seconds. Growth exponent exp = ln(t2/t1)/ln(N2/N1):
# 1.0 = linear; 2-3 = quadratic/cubic.

## Post-fix (on branch perf/compile-scaling, fixes 1-6 below)
# Measured as median of 11 runs on a 2-vCPU Debian 13 box; sub-second sizes are
# noise-dominated, so exponents below 2k are indicative only.

### functions shape
   N       subc(s)   exp   vs pre-fix
   250     0.009     -     ~25x faster
   500     0.018     1.0   ~58x faster
   1000    0.068     1.9   ~104x faster
   2000    0.111     0.7   ~380x faster
   4000    0.570     2.3   ~350x faster
   8000    1.71      1.6   -

### variables / nested / chain / strings
   All linear with small constants (fixed costs dominate below 2k):
   variables 4000: ~0.29s   nested 4000: ~0.04s   chain 4000: ~0.5s   strings 4000: ~0.6s

Target met: 2000 functions compile in ~0.1 s (requirement: < 1 s) and the
1k->2k exponent is approximately linear once fixed per-compile costs are
out of the way; the remaining per-function cost is dominated by lexical
analysis, parsing and the (now linear) semantic/inference passes, each O(N).

Fixes applied (one commit each, on perf/compile-scaling):
  1. perf(infer): hash-table variable/element registries keyed by (owner, name)
     with interned names; growable function table (was capped at 512).
     Replaces O(total vars) linear scans in var_lookup/var_record/elem_lookup/
     elem_record with expected O(1). Was 53% of profiles (9.5M calls).
  2. perf(infer): collect call sites once and replay the indexed list for each
     fixpoint round instead of re-walking the whole AST per round. Same rounds,
     same merge order, identical types; O(sites) per round.
  3. perf(infer): single-visit AST walks (visited node set) for all whole-AST
     passes (collect_functions, infer_var_decls, stamp_empty_array_elems,
     propagate_var_types_to_identifiers, normalize_builtin_methods, ...).
     Statements live on both `next` chains and `children[]`, so the naive walk
     visited each statement of an m-statement block O(m) times.
  4. perf(semantic): exit_scope removes the leaving scope's entries as a
     contiguous prefix of the symbol-table chain instead of re-scanning the
     whole table (O(table) per exit -> O(entries leaving)).
  5. perf(infer): var_tab_find compares interned pointers with strcmp fallback,
     so recorded (interned) names and raw lookup names match.
  6. perf(native): bump heap 64 MB -> 2 GB (demand-zeroed, no disk/RSS cost
     until touched). Fixes string_ops.sb segfaulting on ~1 GB of cumulative
     string concatenation churn (the bump heap never reclaims).

## Notes
- `subi` (interpreter) scales linearly for all shapes; it does not run
  inference.
- `sub file c` (C backend) tracks `subc` closely; it additionally invokes the
  host C compiler (gcc -O2).
- Generated code is unchanged: ELF and C-backend outputs for every file in
  tests/, examples/, applications/ and stdlib/ are byte-identical, or produce
  identical program output where the native/C-backend fallback choice differs.
